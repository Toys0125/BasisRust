# v56 interoperability test report (2026-10-15)

The pinned upstream BasisVR client source is `experimental-branch-major-changes` at `79aac88f38fe2366ff8cbc239742a7f419ffa409`. The Rust server/client baseline is `ac101466fbe2808ab20cdca495f1b638a543360d`, with the Rust client receive-path fix in this change: reliable resource-ID assignments, live scene channel 24, and image-cache offers/replays on `DIRECT_SCENE_SERVER` channel 57 now reach their consumers instead of being ACKed and discarded.

The upstream C# suite passed **2167/2167 tests**. Saved results are in `captures/interop-v56-20261015/csharp-tests/summary.json`.

Rust clients against the upstream C# server passed the combined v56 auth, avatar, scene, and voice run. Three clients authenticated; avatar observation accepted 706 items, including 698 deltas, with zero decode errors, unapplied deltas, missing peers, or stale peers. The combined scene observer received 164/164 expected messages (100%), and voice received 1,928 unique packets with zero duplicates or reordering and no self-receipts. Separate exact scene runs also passed: reliable delivered 100/100 expected messages (102,400 bytes), and unreliable delivered 102/102 (4,896 bytes). See `rust-to-csharp-combined-final/summary.json`, `rust-to-csharp-scene-reliable/summary.json`, and `rust-to-csharp-scene-unreliable/summary.json`.

The upstream C# console against the Rust server passed bundled avatar, additional avatar data, and native Opus voice checks. It observed 604 pose frames from three senders, 106 face keyframes, 540 face deltas, 28 bundled keyframes and 144 bundled deltas with zero parse/order violations, and 2,132 voice packets across six streams with zero loss or reordering. The check confirms the native Opus encoder was active. The upstream C# library harness also passed wrong-password rejection, two-client exact chat/scene/voice/additional-avatar/net-ID assertions, and a fresh authenticated reconnect; see `csharp-library-to-rust-validated/summary.json` and its JSON reports.

The final Rust-to-C# resource run passed all 11 edge checks, including wrong-password and wrong-application rejection, fresh v56 reconnect, clean drain, and image integrity. It completed 9/9 live transfers and 3/3 cached downloads (three 5 MiB uploads; 3,840 unique chunks; zero missing chunks, malformed payloads, integrity failures, duplicates, or fragment errors). The receive-path fix handles assignment and live scene channel 24 plus cached scene channel 57. Results are in `rust-to-csharp-edge-final/summary.json` and `rust-to-csharp-edge-final/images.jsonl`.

These are headless tests. The console uses the real upstream networking, serializers, DID exchange, sealing, and Opus encoder, but does not exercise Unity rendering, a headset, or microphone capture. The upstream console needs its bundled Linux OpusSharp native library; the system `libopus.so.0` lacks the shim symbols and caused a random-byte fallback in preliminary runs. The passing run exposes upstream `Basis/Packages/com.avionblock.opussharp/Plugins/linux-x64/native/opus.so` as `captures/interop-v56-20261015/native/libopus.so` through `LD_LIBRARY_PATH`. No upstream source or global library was changed. Focused Rust checks also passed: 151 passed, 3 ignored; formatting and Clippy were clean, and the final CodeRabbit review reported no findings.

These small loopback runs do not establish WAN behavior, large-player-ID compatibility, load capacity, every feature, or exhaustive security correctness. The upstream pose observer lacks a malformed-delta counter, and its voice observer lacks a malformed-payload counter; reverse-direction cleanliness uses the available counters, logs and the supplemental exact-payload harness. Compression/deltas remained enabled for the official console; the typed harness disabled avatar bundling/deltas to assert exact direct payloads. Cache replay was tested only Rust-client to C#-server.
